# 星星答题（Star Quiz）

**让孩子主动多练几次的答题游戏**：孩子答题攒星星，星星兑换真实奖励，下一个兑换项由家长与孩子在提议板上协商；本地优先、多设备经云同步，学习信息只服务短期、不做长期留存。

> **这是一个自用优先的家庭项目。** 它按一个真实家庭自己的节奏和需求迭代。欢迎围观、fork、提 issue——它们是留言板，不是工单，没有 SLA。

***

## 一、这是什么

面向**单个家庭**的儿童答题游戏：Vue 3 PWA 前端 + 自研薄同步后端，数据本地优先存储、按需与家庭云端同步。

- **理念**：不是「检验孩子学会没有」的刷题工具，而是提升练习意愿与次数的练习引擎——不检验、不惩罚，把「再练一次」变成孩子自己想要的事。
- **数据边界**：无账号、无埋点、不做长期画像；孩子的答题记录只在家庭自己的设备之间同步、短期滚动保留。**代码公开（本仓库），数据私有。**

## 二、初心

这个项目的初心很简单：给自己的孩子做一个答题 App，让他愿意多练一练那些大人看来简单、他却还需要重复的知识点。

有了 AI，生成代码的成本趋近于零——但我不想生成 spaghetti，我想做 clean code，这大概是个人洁癖。

这份洁癖的实现不瞒人，也不是我发明的：工作方法直接站在 [Matt Pocock](https://github.com/mattpocock) 的 [skills 框架](https://github.com/mattpocock/ai-dev-tools)上——需求先拷问成 Spec、拆成票据、TDD 实现、按票验收、复盘归档，这套流程是借鉴他搭好的体系跑起来的，本仓库的协作规约也由此而来。在脚手架之上，才长出这个「家庭自用 App」里不太常见的东西：成套的单元与验收测试、一张每个术语都注明「不是什么」的领域词汇表（`CONTEXT.md`）、18 条连被否决方案都留档的架构决策（`docs/adr/`）。AI 负责产出，纪律负责让产出保持干净——纪律的脚手架来自 Matt，感谢他把这套东西开放出来。

如果你也有孩子，可以直接打开 **https://starquiz.link** 用起来：不创建家庭就能答题，数据完全存在你自己的浏览器里（本地优先，无账号，不收集个人信息）；创建了家庭，多设备再经你自己的云端同步。

至于节奏：开学后的孩子忙于别的，每每到假期这个 App 才被想起、被用起来。我持续维护，懒更新。

## 三、你看到的是「展厅」，不是「工作室」

本仓库是一个按**允许清单**从私有工作室仓策展投影出来的公开快照（决策记录见 [ADR 0018](./docs/adr/0018-工作室与展厅两仓制.md)）：

- 工作室是真实开发现场——issue 讨论、过程资产、运营材料，永远私有；
- 展厅只展出值得被看的部分：代码、测试、领域术语表、ADR、智能体协作规约；
- 展厅的 git 历史是「展览目录」：每次同步一个策展提交，与开发历史无关，落后于工作室是常态。

## 四、技术栈与架构

```
前端  src/          Vue 3 + TypeScript + Vite + vue-router（hash 路由），PWA
后端  worker/       Cloudflare Workers + D1（配对 / 批准 / 同步 / 快照 / 管理）
游戏  public/games/ 内嵌小游戏，经宿主通信协议接入
```

- 测试：Vitest + happy-dom + @vue/test-utils，单元测试与验收测试（`tests/acceptance/`）同仓
- CI：GitHub Actions（Node 22），主 App「构建 + 全量测试」「Pages 静态托管回归」与 Worker「类型检查 + 测试」三轨

## 五、本地开发

```bash
npm install        # 前端依赖
npm run dev        # 开发服务器
npm test           # 全部测试
npm run build      # 类型检查 + 生产构建

cd worker          # 同步后端（独立 npm 项目）
npm install
npm test
```
