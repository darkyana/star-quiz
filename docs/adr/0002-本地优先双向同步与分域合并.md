# 本地优先双向同步与分域合并语义

> **口径注记（2026-09-20）**：本文的合并语义仍然有效；但①测试模式相关表述为历史口径（全量移除见 ADR 0011），②同步触发「写入即推 + 冷启动拉合」后经 ADR 0009 修订为「冷启动 + 导航 + 写后推」。以两份后续 ADR 为准。

star_quest 从纯本地单机走向多设备（孩子用家长 iPad、家长用 iPhone/Mac），数据安置定为**本地优先 + 双向同步**：每台设备保留全量本地副本（离线照常答题），云端做汇合点而非真相源。合并语义按数据域拆分（决策票 #82，2026-08-30 两轮拷问锁定）：

- **纯追加流水**（星星流水、逐题答题记录、出词引擎增量）：按条目唯一 id **并集**，幂等去重。余额恒 = Σ流水实时求和、不落盘（既有 C2 约束），并集合并后天然自洽。
- **可编辑实体**（兑换目录、提议板、进行中兑换）：**记录级 LWW**（最后写胜）。提议板 LWW 与「修订即认同」自洽——并发退化为顺序语义：后写方即修订方，先写方需重新表态。
- **题库**：家长单写，最后导入方胜（整组）。
- **设备本地键**（测试模式开关/快照、数据版本号、上次导出时间）：**永不同步**。

## Considered Options

- **仅无感云备份（单向镜像）**（否决）：只治「怕丢数据」不治「借设备摩擦」，两台设备各过各的、靠手动导文件接力，延续现状割裂。
- **云优先（服务端真相源 + 本地缓存）**（否决）：断网即瘫，与现役纯本地体验倒退，把命交给云端可达性。
- **服务端强一致校验兑换余额**（否决）：家庭激励账本非银行，偶发「合并后短暂负余额」的 worst case 只是下次兑换被余额校验拦住、等答题补回，无真实损失；强一致会杀死离线体验。
- **提议板字段级合并保双方表态**（否决）：会造出「点头落在别人改过的版本上」的语义怪物，与修订即认同直接冲突。

## Consequences

- 同步触发 = 写入即推增量 + 冷启动全量拉合，无长连接（家庭双人同时在线概率低，不养 WebSocket）。
- 云端保留当前态 + **每日快照 × 30 天**，误操作由家长场景整包回滚——LWW 会忠实同步误操作，快照是唯一的后悔药。
- 换机/新设备配对后首次同步**云端为准**全量灌入，覆盖前本机数据自动导出文件留档（不弹选择题）。
- 云上全量明文、单家庭隔离、HTTPS 传输；学习/经济文件导出契约（逃生舱）任何阶段不得破坏。
- 同步引擎与时钟裁决（本地时间戳为主、id 字典序平手，引擎提供服务器时钟则兜底校正）由后续引擎选型票验证，属实现层缺口。
