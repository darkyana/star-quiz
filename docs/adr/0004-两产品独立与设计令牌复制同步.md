# 两产品独立与设计令牌复制同步

> **状态：已废止（2026-09-07，#175）**——老板拍板移除 tools/xingxing-parent 家长端工具，目录与验收链已删除。本 ADR 按文末预置条款自动降级为历史记录；令牌同步债机制随工具删除一并消失，App `src/styles/variables.css` 恢复唯一令牌源地位且无复制方。

star_quest 与 tools/xingxing-parent（星星家长工具）是两个独立产品：独立 package、独立 node_modules、独立 vitest、独立发布节奏（工具走 vite-plugin-singlefile 单文件交付）。二者「有关联」仅体现在共享同一套设计语言——实现方式为**令牌同值复制**，不是引用。

- App `src/styles/variables.css` 是唯一令牌源；工具端 `tools/xingxing-parent/src/styles/variables.css` 全量同集复制，另含工具专属 `--row-*` 表格密度组（不参与比对）。
- 同步契约由 `tools/xingxing-parent/src/styles/__tests__/variables.test.ts` 锚定：同名同值无漂移 + 同集无遗漏。测试转红 = 同步债到期（#71 即该机制正常报警）。

## Considered Options

- **工具端直接 import App 令牌文件**（否决）：跨包引用打破独立构建边界，App 重构/移动文件会连锁弄坏工具构建，工具单文件构建被迫拖 App 源码树。
- **抽共享包（packages/tokens）单一真相源**（暂否决，留作重议）：可消灭同步债，但引入 monorepo 包管理与两产品耦合，当前规模不值。

## Consequences

- 同步债是该模式的常态成本：App 令牌变更后需开小票人工逐字复制，测试即规约。
- 重议触发条件：同步票变频繁（约每月 >1 张）或令牌规模失控时，重开共享源方案。
- 2026-08-30 老板拍板「先复制」；后续同步票以此为决策依据，不再重复解释。
