# 同步域 D1 库表定稿与逃生舱契约门禁

> **编号说明（2026-09-20）**：仓库内另有一份 `0005-大屏断点与流式令牌.md`，编号重复系历史遗留、暂不重号（全仓约三十处「ADR 0005」引用均指同步/库表语义）。凡涉同步、库表、逃生舱的「ADR 0005」皆指**本文**；涉大屏断点与设计令牌的指另一份。

ADR 0002 分域合并语义（流水按 id 并集 / 实体记录级 LWW / 提议板 LWW×修订即认同 / 题库家长单写 / 设备键永不同步）与 ADR 0003 Cloudflare Workers/D1 载体的 P0 落地定稿（票 #119，依据 #82/#83/#86）：同步域表结构定稿、家庭租户边界、Worker 骨架边界，以及「逃生舱契约 = 迁移每阶段验收门禁」成文。

- **域模型映射原则**：合并语义由库端**结构与约束**承载（并集 = 复合主键幂等去重；记录级 LWW = updated_at 裁决列 + 删除墓碑），合并**逻辑**仍客户端为主（ADR 0003「薄同步」定位）——库端零业务逻辑、零触发器。
- **家庭 = 租户边界**（2026-09-02 老板补充，第二家庭在途）：全部同步域表主键以 family_id 打头，一切读写按家庭过滤；配对码全服唯一；快照/导出按家庭隔离。多家庭租户从第一天进 schema，成本近零（#87 容量口径：免费档富余 3 个数量级，两家庭共享同一部署远未到顶）。

## 域模型映射（ADR 0002 → D1 表）

| ADR 0002 分域 | 本地键（sq_*） | D1 表 | 合并语义的库端承载 |
|---|---|---|---|
| 纯追加流水——星星流水 | sq_stars | star_entries | 主键 (family_id, id)：同 id 重复上传幂等 = 并集；余额仍 Σ流水实时求和不落盘 |
| 纯追加流水——逐题答题记录 | sq_question_results | question_results | 主键 (family_id, question_id, answered_at)：本地记录无独立 id，条目身份 = 题目 × 作答时刻（同轮共享同一时间戳，天然不撞） |
| 纯追加流水——出词引擎增量 | sq_recent_words | word_appearances | 主键 (family_id, word_id, appeared_at)：本地 seq 是设备局部轮次序号、跨设备不可比，云端条目身份取出现时刻（保守落位，缺口见 Consequences） |
| 可编辑实体——兑换目录 | sq_rewards | reward_items | 记录级 LWW：updated_at 裁决 + deleted 墓碑（经济文件整体替换 = 存量打墓碑 + 新项 upsert） |
| 可编辑实体——提议板 | sq_proposals | proposals | 记录级 LWW×修订即认同：修订 = 客户端整行重写（修订方自动同意、对方重置的联动在写侧完成），库端只存最后写——并发退化为顺序语义由 LWW 天然承载 |
| 可编辑实体——进行中兑换 | sq_active_redemptions | active_redemptions | 记录级 LWW：核销/放弃 = deleted 墓碑（删除必须可传播） |
| 红旗标记（保守补位） | sq_flagged | question_flags | ADR 0002 未显式枚举；按可编辑实体记录级 LWW 落表（取消标记 = 墓碑），缺口见 Consequences |
| 题库 | sq_questions | question_banks | 每家庭一行整组 JSON：家长单写、整组 LWW（updated_at）——「最后导入方胜（整组）」的忠实承载，不逐题展开 |
| 设备凭据（服务端自有，非合并数据） | ——（#84 配对域） | families / pairing_codes / devices | 租户根、配对码→家庭映射、设备名册与凭据摘要 |
| 设备本地键 | sq_test_mode / sq_test_snapshot / sq_data_version / sq_last_export | **云端零表** | 永不同步（ADR 0002 拍板）；测试期静默由客户端「不推不拉」实现 |
| 每日快照（P1 实施） | —— | family_snapshots | 结构随本定稿先行落库（ADR 0003 已锁 Cron ×30 天），按家庭隔离 |

各表列结构以 `worker/migrations/0001_init.sql` 为准，速览：

- families(family_id PK, created_at)——租户根，family_id 为 UUID
- pairing_codes(code PK, family_id FK, issued_at, retired_at)——retired_at NULL = 现役；重置 = 现役码打戳 + 新码插入（重置只拦后续加入，已配对设备不受影响，#84）
- devices(device_id PK, family_id FK, name, role ∈ {parent, child}, credential_hash, paired_at, last_seen_at, revoked_at)——凭据只存摘要；移除设备 = revoked_at 打戳（断云不擦数据，墓碑防凭据复用）
- question_banks(family_id PK/FK, content JSON, updated_at, updated_by, server_at)
- star_entries(family_id+id PK, timestamp, type ∈ {earn, redeem}, amount > 0, source, quiz_id?, server_at)
- question_results(family_id+question_id+answered_at PK, outcome ∈ {correct, wrong, skipped}, server_at)
- word_appearances(family_id+word_id+appeared_at PK, server_at)
- reward_items(family_id+id PK, name, price > 0, emoji?, updated_at, updated_by, deleted, server_at)
- proposals(family_id+id PK, name, price, status, createdAt/updatedAt 口径 created_at/updated_at, description, parent_status, child_status, initiator, last_action_by, last_action_kind, deleted, updated_by, server_at)——字段与本地 ProposalRecord 落盘 12 字段一一对应
- active_redemptions(family_id+id PK, reward_id, name, emoji, created_at, updated_at, updated_by, deleted, server_at)——name/emoji 为兑换瞬间快照，展示不依赖 reward_id
- question_flags(family_id+question_id PK, flagged_at, updated_at, updated_by, deleted, server_at)
- family_snapshots(family_id+snapshot_id PK, taken_at, content JSON)——保留窗口 ×30 天由 P1 Cron 清理

公共约定：时间戳统一 Date.now() 毫秒（INTEGER），唯 answered_at 保留本地 ISO 8601 字符串（QuestionResult.timestamp 原样，TEXT）——映射忠实于本地形态优先于库端整齐；LWW 裁决主依据 = updated_at（客户端写时刻，本地时间戳为主，平手裁决归 P1 引擎），server_at（Worker 接收时刻，逐表皆有）为时钟偏移兜底与增量拉取游标候选；除 question_banks/families 外全部表 family_id 进复合主键打头。

## 家庭租户边界

- families 为租户根表；全部同步域表 family_id 外键指向它且进主键——隔离在行级成立，跨家庭读取无路径（P1 查询一律按 family_id 过滤）。
- pairing_codes.code 为**全表主键**（非按家庭分区）= 配对码全服唯一。
- 快照/导出按家庭隔离：family_snapshots 主键含 family_id；`wrangler d1 export` 逃生舱导出按家庭过滤（P1 实施要求）。
- 配对端点防爆破：6 位码空间仅 10^6，**配对端点限速 + 失败锁定**列入 P1 实施要求清单（结构已备：credential_hash 只存摘要）。

## Worker 骨架边界（本票落地）

worker/ 为仓库第三个独立包（同 tools/xingxing-parent 惯例：独立 package-lock、独立 CI job）：`GET /healthz` 静态存活检查；`GET /readyz` 对 D1 `SELECT 1`（验证绑定与迁移就绪）；CORS 允许源从 env `ALLOWED_ORIGIN` 读、非允许源 403（dev 默认 `http://localhost:5173`；生产域名与真实 D1 database_id 均为部署时老板侧输入，仓库内不出现）；migrations/ 版本化迁移。**不含任何同步业务语义**——增量上传/冷启动拉取、服务器时间戳、每日快照 Cron、家庭码门禁全部 P1（ADR 0003 Consequences）。

## 逃生舱契约门禁（成文规则）

**「学习/经济文件可导出、导出测试全绿 = 云迁移每阶段的验收门禁」**：任何迁移阶段（P0–P3）验收时根套件必须全量绿，导出契约测试红即验收不过——云同步永不剥夺「带着数据离开」的能力（ADR 0002 逃生舱条款、#86 常驻原则）。

- 现役锚点：`tests/acceptance/34-export-contract.test.ts`（R36 导入导出契约验收：导出形状、文件名、字段边界）、`tests/acceptance/16-import-export-pure.test.ts`；单测侧 `src/utils/__tests__/importExport*.test.ts` 与 `src/composables/__tests__/useExport.test.ts`。
- 本票验收即执行该门禁（根套件全量绿，见票内交付记录）。

## Considered Options

- **每域整包 JSON 单行（域级 LWW）**（否决）：两设备并发写即整域覆盖丢增量，记录级合并语义没有承载结构，云端「保留当前态」退化为「保留最后一包」。
- **事件溯源（append-only 事件日志，云端无当前态）**（否决）：冷启动需全量回放合并，与 ADR 0002 已拍板的「云端保留当前态 + 每日快照」冲突；日志可作 P1 观测增强，不作主结构。
- **库端触发器/存储过程承载合并**（否决）：D1 薄同步定位是结构承载、合并客户端为主（ADR 0003）；库端逻辑会把合并语义分裂两处。
- **题库逐题建行**（否决）：题库合并语义是「整组胜」不是「逐题胜」，逐行展开与语义不匹配且组完整性无约束；整组 JSON 一行（KB 级）无压力。
- **多租户按 database 分家庭**（否决）：绑定数与迁移管理复杂度直线上升，行级 family_id 已满足隔离，免费档容量富余（#87）。

## Consequences

- `worker/migrations/0001_init.sql` 落全部 12 表，只建结构零业务数据逻辑；后续 schema 演进走版本化迁移（0002 起），禁止改写 0001。
- Spec 缺口（ADR 0002 未显式枚举的本地键归属，保守落地待 P1 收口）：红旗 → LWW 实体（已落表）；出词引擎 seq → 出现时刻身份（已落表）；sq_proficiency / sq_quiz_mode / sq_session → 未进同步域（云端零表，P1 引擎票重审）。
- 逐题答题记录云端全量保留；本地「最近 5 次」滚动窗口为客户端展示派生，窗口与全量的收敛归 P1 拉取协议。
- 部署验证为老板侧输入：真实自定义域名、Cloudflare 账号、D1 database_id；部署后健康检查经大陆网络 curl 可达（#80 事实依据）方可收 P0。
- P1 实施要求清单：同步端点（增量上传/冷启动拉取）、服务器时间戳、家庭码配对（含防爆破限速/失败锁定）、每日快照 Cron ×30 天（family_snapshots 保留窗口清理同批）。
