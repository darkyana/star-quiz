# 孩子维度先行

学习与经济数据行自下一次数据版本演进起即携带孩子归属字段(childId),现阶段恒为默认孩子、前端保持单孩体验;多孩(#134)到来时只演进前端流程,数据从 1 到 n 打开、零迁移。兑换目录与题池为全家共享、不挂此维度;提议板挂维度,其「所有人都要同意」的家庭共识状态机随多孩体验票另议(老板拍板 2026-09-07,数据方案模型轮)。

## Considered Options

- **等多孩落地再加维度**(否决):届时同步 schema、行合并键、导出契约的改动面随数据量与版本数放大,且新功能会继续把单孩假设焊进结构。
- **现在建完整孩子档案域**(否决):档案属性需求未明,为想象买单;先带维度、后建档案。

## Consequences

- 数据版本断代一次(8→9),学习/经济导出契约与云同步 D1 schema 同步演进;「断代迁移体验」单列一票(迁移对用户无感、迁移前备份确实落地、同步端重新基线)。
- 星种(CONTEXT.md 兑换节)与题库大类/分册两处新维度、题目结构泛化(wordId 可空 + type 加 trivia)宜同批落地,共用同一次断代。
