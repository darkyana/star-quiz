# 运营方发码制——建家收权与双因子占家闸

家庭码从「任何人首配自建家庭」收归运营方签发:运营方经本地脚本直接在库内建空家并成对签发码与口令,无管理端点、无 ADMIN_TOKEN,公网零新增面,发码权限即 Cloudflare 账号权限;配对端点删除「码不存在+家长角色→建家」自助路径,码不存在与口令不符一律并入与真申请同构的假等待(盲口径不重开)。

空家/无家长设备家庭的直入需要码+口令双因子:单 6 位码可被枚举静默占领无人家庭,是发码制下唯一的接管面;双因子后组合空间 4.6×10^11、限速下暴力期望千年级。码+口令作为家庭钥匙对成对签发、家长重置时成对轮换,灾难恢复保持自助;直入条件定为「无现役家长设备」而非「零设备」,以兑现移除设备词条的恢复承诺(家长设备全丢但孩子设备健在时不再死锁)。

## Considered Options

- 「首台家长走申请、运营方批准」:安全最强,但每家庭入驻多一次运营方往返,败给双因子直入的自助体验
- 运营方管理页 + ADMIN_TOKEN:公网多一个可探测面与可泄露凭据,败给「脚本直达 D1」
- 家长重置换码造不出新家庭,故保留(闸门在「谁能建家」,不在「谁能换钥匙」)
