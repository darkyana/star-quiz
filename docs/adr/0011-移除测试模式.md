# 移除测试模式

## 背景

测试模式诞生于家长孩子共用一台设备的时代：家长想试答时，需要一个「带回滚的临时数据沙盒」——开启时快照星星流水与逐题答题记录两域，期间数据照常写本机但云同步静默（不推不拉），关闭时原子回滚，保证试答不污染孩子数据。多设备支持上线后（孩子设备答题、家长设备管理），家长试答可以直接用孩子端正常流程、答完放弃（不写星星流水、不写临场状态、不写近期已测词），原始场景消失，功能只剩维护负担：同步引擎的静默 gating、学习数据写入路径的测试期分支、未来每个学习域新增先验时的防泄漏心智成本。

[#228](https://github.com/darkyana/star-quiz/issues/228) 拍板全量移除（2026-09-10，内测家庭尚未开始答题的零成本窗口）。

## 决策

全量移除，不设替代功能。家长试答口径 = 孩子端正常答题 + 放弃：放弃轮不写星星流水、不写临场状态、不写近期已测词，仅已答的题照写逐题答题记录（对新题优先不再是新题、答错题临时进错题池且连对两次自愈）——该残留已接受为内生代价。升级语义：删除版覆盖到正处于测试模式开启中的设备时，测试期数据自然转正上云，不写迁移；设备残留的 `sq_test_mode` / `sq_test_snapshot` 键无消费者、不清理。

## 理由（ADR 三条件自检）

- **难逆转**：快照-静默-回滚子系统连同三个专项验收套件整体删除，回头重建成本等于重做。
- **事后会问**：仓库里曾有测试模式（ADR 0002/0005/0009 仍提及其静默口径），为什么没了？——本 ADR 回答：场景随多设备消失。
- **真实权衡**：保留方有真实价值（经济侧试错不可手工修复——超能力奖励只能加星不能减星），因原始用户场景消失而被压过。

## 后果

- 历史 ADR 0002/0005/0009 中「测试模式零推零拉/永不出本机」表述自此为历史口径，不回改。
- 移除完成的可验证定义固化为源码级守卫测试（tests/acceptance/39-no-test-mode.test.ts，沿 32 号验收源码文本断言先例）。
- 家长页职责清单不再含测试模式（ADR 0010 背景段中的列举为历史口径）。
