# 删发布窗口:发布门禁 = 发布门槛

## 背景

发布窗口是控时发布特性(R33)的一部分:每天 20:00–21:00(设备本地时间)半开区间内才允许发布已达成一致的提议,窗口外家长既无发布按钮、发布动作也返回 `out_of_window`;家长超能力随之长出「越窗发布」旁路(开启时仅跳过窗口检查)。实际使用中窗口被证明没必要——双方同意后家长要的是立即发布,而不是记住并等待某个时段;时间窗催生的旁路逻辑进一步说明约束本身站不住。

[#265](https://github.com/darkyana/star-quiz/issues/265)(属 [#261](https://github.com/darkyana/star-quiz/issues/261))拍板全量删除发布窗口。

## 决策

发布窗口整体删除,不设替代:`PUBLISH_WINDOW` 常量、`isInPublishWindow` 纯函数、提议板列表上方窗口说明行(`publishWindowHint` 槽位)、门禁的窗口分支与 `out_of_window` 原因码、`publishGate`/`publish` 的 `now` 与 `superPower` 参数(越窗旁路随窗口消亡)全部移除。发布门禁自此 = 发布门槛(双方同意 + 非终态),门槛就绪家长端任意本地时间即见发布按钮并可发布;按钮显隐与发布动作仍共用 `publishGate` 单一判定,规则只此一份。修订即认同、作废、双方表态等提议语义不动;已作废删除与超能力奖励归 #266。

## 理由(ADR 三条件自检)

- **难逆转**:窗口常量、判定函数、门禁原因码、页面说明行与整套越窗旁路测试一并删除,重建等于重做 R33。
- **事后会问**:仓库里曾有"每天 20–21 点才能发布"的规则,为什么没了?——本 ADR 回答:窗口被证明是人为拖延,删除后门禁规则简单到能向孩子一句话说清。
- **真实权衡**:窗口方有真实价值主张(仪式感、防止冲动发布),但没有任何家长行为依赖它,而旁路逻辑的存在恰是对它的持续否定。

## 后果

- CONTEXT.md「发布窗口」「超能力发布」词条删除,「发布门禁」改写为 = 发布门槛;「家长超能力」词条中"越过发布窗口"表述随窗口消亡(词条整体收敛归 #266)。
- `PublishGateResult` / `PublishResult` 的 `out_of_window` 原因码不复存在;未来同名硬检查仍挂 `publishGate` 单一判定与 `validate` 校验 seam。
