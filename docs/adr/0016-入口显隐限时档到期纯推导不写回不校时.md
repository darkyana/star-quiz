# 入口显隐限时档:到期纯推导,不写回、不校时

## 背景

入口显隐原是两档开关(开/关,未设置即隐藏),家长想"现在能玩、只玩一会儿"时只能开着靠记忆到点手动去关。[#279](https://github.com/darkyana/star-quiz/issues/279)(承 [#277](https://github.com/darkyana/star-quiz/issues/277))拍板升级为四态单选:关闭 / 保持开启 / 限时开启(半小时或一小时),到点自动回到关闭态。

## 决策

**① 到期 = 纯推导,无写回。** 入口可见 = 保持开启,或(限时开启 且 当前时刻在到期之前)。任何设备任何时刻自行推导,到点那一刻仅是界面呈现变化,不产生同步写入;到期后家长页控制组回到未选档初始状态,同样由推导得出。

**② 到期时间戳以家长设备本地时钟为基准,不做服务器时间校准。** 写入方按自身本地时钟算出到期时刻,各设备推导时拿本地当前时间直接比较;接受设备间分钟级偏差。

**③ 与 ADR 0015(删发布窗口)的关系:语义不同,维度相邻。** 当时删的是**开局时窗门禁**——家长发布动作受每天固定时段硬限制,证明是人为拖延而整体删除;本次引入的是**家长限时授权**——家长主动给孩子一段有界的开放时间,是控制能力的增强而非回归。两者都是入口/动作的时间维度,方向却相反:0015 去时间化(发布与时间无关),本 ADR 给入口显隐补上时间维度(限时授权)。未来读者不应由 0015 推断"本仓永远不给入口加时间约束"。

## 理由(ADR 三条件自检)

- **难逆转**:四态档位编码与到期字段已进同步域并跨协议版本传播,回退两档开关需迁移存量数据与全链路校验规则。
- **事后会问**:到点是谁关的?没有设备在线会不会开着?为什么不做时间校准?——本 ADR 回答:没有"谁"在关,每台设备对照自身时钟推导即可,全家无设备在线也正确呈现关闭态;家庭场景分钟级偏差无实质影响,本地存储本就可被篡改,时钟不是攻击向量。
- **真实权衡**:写回方案(某设备到点把行覆写为关闭)可让记录即时反映最终状态,但引入"谁在场谁写"竞态——全家无设备在线时记录停留过期态,需额外补写逻辑;服务器校时可消偏差,却为无实质影响的家庭误差引入网络依赖与失败路径。两者都败给纯推导。

## 后果

- CONTEXT.md「入口显隐」词条改四档口径,新增「限时开启」「到期时间戳」词条。
- 到点无提示、无通知、无后台任务:前台设备限时生效期间以分钟粒度重算推导刷新界面即可;倒计时文案(剩余 X 分钟 / 不到 1 分钟)只在孩子端入口说明弹窗内呈现。
- 限时进行中改档即覆写该行走既有最后改动方胜同步;选保持开启清除到期时间戳,重选限时从当下重新起算。
