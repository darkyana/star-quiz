# 惊喜题集挂载契约:题集对象、单现役槽位、规则随内容分发

内置惊喜内容从散装 TS 常量(`builtin-trivia-questions` 等,类别/分册常量名与实际内容漂移、换主题撞墙)升级为**题集对象**,惊喜答题与学科共用的「答对即得星」链路拆开:惊喜默认不产星,题集可自带得星规则。[#286](https://github.com/darkyana/star-quiz/issues/286)(承 [#287](https://github.com/darkyana/star-quiz/issues/287) 资产槽位 / [#288](https://github.com/darkyana/star-quiz/issues/288) 零星默认 / [#289](https://github.com/darkyana/star-quiz/issues/289) 得星规则 / [#290](https://github.com/darkyana/star-quiz/issues/290) 得星开关与家长面板)拍板如下。

## 决策

**① 题集对象 + 现役资产槽位,换内容零代码。** 内置惊喜内容收敛为题集对象——名称(题库大类/分册,调度范围键)、孩子侧介绍、惊喜得星规则(可缺省)、题目数组、贴纸画作引用;载体是仓库静态资产目录的固定现役槽位 `public/trivia/current/`(set.json 头部元数据 + 题目数组,题目不携带 category/book、加载时由头部统一盖章,避免两处漂移)。App 冷启动预热 fetch → 校验(头部名称非空、题目 ≥3 道、id 全 9 号段且唯一、题目形状合法且无词归属、规则形状合法)→ 并入惊喜调度池(仅内存合并,不进用户题池);任一失败视为惊喜题库为空,绝不带病入池。换内容 = 整夹替换 current/ + 旧夹移入旁边归档目录 `public/trivia/archive/`(**App 永不读取归档**,9 号段顺延续号、归档序号永不复用)+ 跑测试,全程零代码路径;出题产出契约由 prompt 模板文档承载,外部 AI 出题、人工核对后入库。

**② 单现役槽位,数据形态留多集并存路。** 题集对象按对象数组形态建模,同一时刻恰一个现役(首页仍一个贴纸);将来多主题同挂只扩运营形态,不迁数据。本票不做多贴纸多入口(运营形态另议)。

**③ 惊喜得星规则随内容分发,缺省无奖励,开局快照、结算不反查。** 规则 = 门槛数组 `{ 正确率下限, 星数 }`,挂在题集对象头部:随内容上架而设定、下架而自然消失,历史已入账流水不动;不含此字段 = 纯玩内容零配置上架、惊喜轮不产星(#288 起默认)。开局(startQuiz)把现役规则的**深拷贝快照**写进会话(starRule 字段,与 mode/scope 同级);结算与结果页只读快照、绝不反查现役题集——App 升级换主题不打断进行中的轮,孩子的成果不被换主题吃掉。结算按本轮正确率(答对数/本轮题数)命中**最高的正确率下限档、只取一档**入账(多档同中不叠乘,无命中 = 0 星);带规则轮写一条 earn 流水,星数按命中档、来源文案「惊喜答题:{类别名}」(类别名取会话 scope 快照,快照式、不反查内容),幂等仍以会话 quizId 为唯一依据;0 星与无规则轮零流水。结果页单分支点 `sessionEarnsStars`:无规则轮显示「答对 X / Y 题」主结果行、无得星数字与星光雨;带规则轮恢复「+N 颗星」滚动数字与满分星光雨。旧会话无 starRule 字段 = 不产星(#288 基线行为不变)。学科得星公式(答对 +1/题、满分 +3 硬编码)零改动。

**④ 得星开关键控入口、不键控主题,只影响新轮。** 家长得星开关为家庭级、默认开,存储与同步搭入口显隐既有同步域(域内独立入口键,行级 LWW 全家生效,ADR 0016 同基座);键由惊喜入口 id 派生(`builtin-trivia:star`)——键控入口不键控主题,换 set.json 内容不重置,换内容不会偷偷把家长关掉的得星重新打开。生效决定只在开局一刻定格:开关关闭时开局不写规则快照(= 无规则 = 零产星),进行中的轮按开局快照照常结算、不受之后改开关影响;孩子端对开关零感知,仅体现在结算行为。家长在入口显隐面板惊喜条目下看到两行全自动组装——主题行「本期为{类别名}:{分册名},{N}道惊喜问答」+ 奖励行(「奖励:无」或按规则档自动渲染),单一事实源 = 现役题集对象与其规则;现役题集带规则时才显示开关控件。

**⑤ 与 ADR 0014 三条契约的兼容:零改动。** 9 号段身份不变——归属仍由 `bankOf` 单点判定(9 号段 → 惊喜题库),题目身份与加载方式无关;规则不参与身份——starRule 只进会话快照,不进题目、不进任何判定链;学习文件闭环零改动——题集仍不经任何 sq_ 键,导入拒收与导出不含照旧,家长工作台仍不承担造图题。

## Considered Options

- **多题集并存、多贴纸入口**:运营形态未定,首页多贴纸 + 家长多套控制为想清楚的场景预付复杂度;对象数组形态已留路,单现役起步、将来扩多集零迁移(败给单现役槽位)。
- **Question 加 theme 字段(主题进题目)**:主题与规则随之参与调度与身份,重蹈 ADR 0014 里 type 兼任两职的覆辙;实现取头部元数据统一盖章,题目内不携带 category/book,两处漂移从形态上消灭。
- **结算时反查现役题集**:App 升级换主题后,进行中的轮会按新内容(或空题库)结算,孩子的成果被换主题吃掉;快照使结算自包含,会话即完整事实。
- **家长面板自由文本(家长自填奖励说明)**:说明与真实规则必然漂移、误导家长;两行由题集对象 + 规则全自动组装,永远与真实规则一致。
- **逐主题(逐题集)开关**:换主题开关即重置,违背「换内容不偷偷重开已关的得星」;键控恒定的入口 id,状态跨题集存续。
- **学科题库接同套得星机制**:学科「答对 +1/满分 +3」是既有硬编码契约,牵动学科结算与全部存量行为;规则字段形态独立、将来可迁移,本票不动(Out of Scope)。

## 后果

- CONTEXT.md 词汇表变更:新增「惊喜得星规则」「惊喜得星开关」词条,「惊喜题库」「内置题集」修订为题集对象口径。
- 无星轮零流水:无规则或开关关闭的轮不写任何 earn 流水,星星流水无痕迹(逐题答题记录照写,学科调度两不相扰);结果页无得星数字与星光雨,差一题满分档改用无星变体文案。
- set.json 缺失/损坏口径:一律视为惊喜题库为空——入口照常显示,点开提示「惊喜内容在路上,重试一下」并可重试,不崩溃、不与家长入口显隐耦合;冷启动预热与重试共用同一加载函数。
- 换主题出题流程在 prompt 模板契约上增加「设定得星规则(可省)」一步;现役首例(塞尔达传说问答)未带规则,即纯玩形态上线。
