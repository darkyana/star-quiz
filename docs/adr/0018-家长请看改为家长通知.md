# 家长请看改为家长通知:贴纸角标、同页两形态、已读账搭入口显隐域

## 背景

「家长请看」原是一次性教程页:贴纸对所有设备常驻,家长无法分辨"有没有新东西",读完也没有收尾出口;运营侧想再说一句话只能往首页或三张卡里塞。[#319](https://github.com/darkyana/star-quiz/issues/319)(经 tickets #320–#324 实现,PR #325)把它改成家长通知的收纳箱 + 首页贴纸角标。

## 决策

**① 贴纸 = 通知角标,孩子设备不显示(修订 #316)。** 首页「家长请看」贴纸的显隐由"未读通知集合是否为空"驱动:有未读即显示、全确认即消失,后续版本新增一条通知即自动重现。孩子设备不显示这枚贴纸——通知的受众是家长,不该由孩子替家长消费;这显式收回 #316 的"入口对所有设备可见"口径,未配对与待批准设备照常显示。文案保持「家长请看」不改措辞;不做未读数、红点或数字角标。

**② 同一路由、两种形态,由显式来源参数区分。** 「家长请看」页缺省恒为通知视图(只显未读、逐条「知道了」、读空见收尾空态);带 `from=parent` 即归档形态(全量渲染、零已读痕迹、无「知道了」、永不空态)。非法/缺失/重复/外部参数一律降级为通知视图,返回回首页——沿用 #317 立下的"显式来源 + 合法值白名单"形状。该参数承担双重含义(归档形态 + 返回回家长页),全仓唯一写入点是家长页「给家长的话」按钮;新增任何写 `from=parent` 的入口即新增一个归档入口,必须显式评审。

**③ 已读账搭既有入口显隐同步域,布尔 + 行级 LWW;不新建域。** 键形 `parent-guide:<通知id>`,值 `true` 表示已读、键缺席即未读;先例是惊喜得星开关键 `builtin-trivia:star` 走同一域,云侧零改动(worker 接受/拒绝矩阵测试证伪了"必须新建域")。只有显式点「知道了」才写状态,不存在"打开即已读"。**迁移触发条件(票面写死):当通知需要布尔之外的第二层状态(送达状态/未读计数/通知类型)时,迁到独立同步域**——在那之前不为假设的需求预付抽象。

## 理由(ADR 三条件自检)

- **难逆转**:孩子设备不显示与"全已读即消失"已改写首页/路由/验收层的硬编码断言(原"首页唯一家长入口""入口全设备可见"锁点均按新语义重写留痕),翻案需连改三层契约;同步域口径若来回摇摆需动 worker 校验。
- **事后会问**:贴纸怎么忽隐忽现?为什么孩子设备没有?一个页面为什么两种样子?`from=parent` 为什么全仓只许一处写?已读为什么搭入口显隐域而不是自己的域?——本 ADR 一并回答,防止后人把①当成回归 bug 修回 #316 口径。
- **真实权衡**:贴纸角标 vs 常驻入口(角标赢在"需要看时才提醒");搭既有域 vs 开新同步域(布尔粒度下既有域零云侧改动即全家一致,开域是为假设需求付真实成本);孩子设备保留 vs 隐藏(通知是家长要消费的东西)。

## 后果

- CONTEXT.md 新增「家长通知」「已读账」「归档形态」词条。
- 通知的内容与身份随版本内置:运营侧"发一条通知"= 发一次版本,身份只增不改(想再提醒同一件事必须换新 id,如 `family-v2`)。
- 状态损坏或被清空的最坏后果 = 通知重新显示为未读,不阻塞任何功能;小工具版(离线单文件)照常本地可用、从不同步。
- 配套埋点 `guide_dismiss`/`guide_archive` 已进共享事件白名单;生产生效需获授权者重新部署 Worker,部署前服务端 400 由客户端静默吞掉,属设计内。
