# 工作室与展厅两仓制:作品化路径与脱敏边界

私有工作室仓(现 `star-quiz-studio`,原 `star-quiz`)是唯一真相源与开发现场;公开展厅仓(`darkyana/star-quiz`,2026-10-02 新建空仓)只接收按允许清单策展的投影,承载「作品化」——把过程与形态中值得被看的部分公开,私人语境永不出仓。背景:内测验证「愿意经营兑换仪式的家庭」稀缺,产品定位收敛为「自用为锚、形态随时欢迎认同者加入」;作品价值(领域建模纪律、ADR 决策链、单人+AI 智能体协作范本)需要可公开的载体。2026-10-02 全量脱敏审计先行(314 issue / 14 PR / 468 评论 / 503 提交 / 923 被删文件 / docs 全目录),拍板如下。

## 决策

**① 单向投影、默认为空。** 工作室 → 展厅单向流动,永不反向合并;展厅内容以允许清单(include-only 的 gallery manifest)定义——不在清单里的路径,含将来新增的一切文件,默认不外漏。以结构性安全替代黑名单记忆:新敏感文件(如含真实凭证的运营文档)静默漏出从形态上不可发生。

**② 策展提交,展厅历史即展览目录。** 每次同步把增量压成单个「展签式」提交(信息形如「2026-10 策展:××」);展厅 git 历史全新——不 rewrite 工作室历史,作者邮箱/主机名/被删文件的历史内容一概不投影。滞后是特性不是债:美术馆不展出未完成的作品。

**③ 脱敏边界固定如下。** 永不投影:issue/PR 全部讨论、`docs/operation/`、`docs/frozen/`(默认)、真实凭证(家庭码/口令只记仓库外台账;2026-10-02 凭证卫生后工作树零真值)、git 历史与作者身份。形态替换:`worker/wrangler.jsonc` → 占位模板;展厅 README 以工作室 `docs/gallery/README.md` 为真相源投影。审计标准归档:未成年人可识别组合、第三方(亲友/内测家庭)痕迹、访问凭证与生产资产为红线;**作者自身语境不默认视为已同意**,逐条由作者定夺。

**④ 社交合同写进展厅 README 首屏。** 自用优先的家庭项目、按自家节奏迭代、issue/PR 是留言板不是工单、无任何 SLA;展厅 issue 默认关闭或仅留 Discussions。

**⑤ 协作与策展门。** NikaStarBot 为展厅 collaborator(write);策展 PR 由机器人开出、作者过目 diff 后点合并——机制自动、判断留人;不存在无人值守的自动发布。

## Considered Options

- **单仓直接转公开**:需 rewrite 503 提交(统一作者邮箱、清除含孩子画像的提交与已删反馈日记)+ 编辑存量 issue + 重排机器人署名,且此后每次迭代都背上「公开商品」包袱(败给结构性隔离)。
- **纯内容(文章/视频,代码不公开)**:零隐私风险,但作品无可验证层,证据力度打折。
- **fork 工作室为公开仓**:fork 携带全部历史与父仓关联,等于单仓公开的全部风险(否决)。
- **GitHub 原生「选择性公开历史」**:平台不存在此能力,私有转公开即全量裸露(不可行)。

## 后果

- 展厅与工作室结构性不同(README / 文件集 / 历史三者皆不同),勿追求一致;展厅可随时删除重建,损失仅一次同步的成本。
- 展厅自跑 CI(build + 全量测试)作为「展览是活的」证明;双仓 CI 分钟数在免费额度内。
- 工作室仓改名 `star-quiz-studio` 后 GitHub 对旧名自动重定向,他机旧 clone 与 CI 不受影响。
- 家庭码 `123456` 为作者知情保留的开发者特权码(威胁模型:猜码仅产生待批准的入家申请,批准权在家长端,拒绝不留痕、探测无数据)——非疏漏,勿在后续票据中当作缺陷修复。
- 此后新增运营类文档默认落在排除区;进允许清单需显式决策并过一遍审计标准。
