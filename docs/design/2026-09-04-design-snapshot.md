# 星星答题 · 设计 status quo 产品说明（2026-09-04 快照配套）

> 本文与 `2026-09-04-design-snapshot.html` 配套：HTML 是视觉与流程快照（21 屏，编号 ①–㉑），本文提供产品语境。两者共同构成「设计 status quo」，供外部 AI 设计工具做突破性风格探索。点时快照，不持续维护；视觉大改后重开票再拍。

## 产品一句话

「星星答题」是给孩子（约小学低年级）的英语答题 + 星星奖励 App：孩子答题攒星星，用星星兑换和爸爸妈妈商量好的奖励。本地优先 PWA，一部设备即可用，两台设备（家长 + 孩子）可经家庭码配对同步。

## 用户是谁 · 双端分工

- **孩子（主用户）**：在一台设备（如 iPad）上答题、看星星余额与流水、兑换奖品、管理自己的「宝藏箱」、在提议板上和父母商量想换的东西。
- **家长（管理者）**：在另一台设备（如手机）上管理题库与兑换项数据（导出/导入）、管理星星流水、生成「出题指令」交给外部 AI 出题、在提议板上表态与发布兑换项、管理家庭设备（配对/移除/家庭码/快照回滚）。
- 未配对的单设备形态：家长入口照常存在（首页页脚「配置」），一切功能本机可用；配对入口（页脚「配对」）只对未配对设备出现。
- 孩子设备构造上不存在家长入口（路由层守卫），家长页的孩子端视角不存在。

## 核心流转一：答题 → 得星 → 兑换 → 核销（① → ⑥）

1. **① 首页（/）**：品牌「星星答题」+ 漂浮大星星 + 当前星星余额（示例 37 颗）。出题方式入口可切换普通/新题优先/错题优先（只影响下一轮）。双按钮：「开始答题」「兑换星星」。页脚：版本号 V0.13.0、「配置」（家长入口）、「配对」（仅未配对设备）。
2. **② 答题页（/quiz）**：每轮固定 10 题，三种题型（看中文选英文 / 看英文选中文 / 挖空选词）。顶部进度条 + 「第 X / 10 题」；题卡右上角红旗钮可标记没把握的题（标记后进错题优先池）；选项四选一或「不会」跳过；作答后即时反馈（答对了 / 正确答案是这个 / 记住它，下次就会了）。顶栏「放弃答题 / 重新开始」均需二次确认。
3. **③ 结算页（/result）**：得分角标（如 9 / 10）+ 得星主视觉「+9 颗星」。计分规则：答对 1 题得 1 星，全对额外奖励 3 星（满分一轮 13 星）。四档鼓励文案（满分通关 / 就差 1 题 / 答对了这么多 / 没关系下次再来）；满分时全屏彩纸。「回到首页」是唯一出口。
4. **④ 兑换页（/redeem）**：顶栏返回 + 余额胶囊。奖品卡列表按价格升序（示例：菠萝油 5 星、看 10 分钟电视 15 星、去吃寿喜锅 25 星、去游乐园一次 30 星、去迪士尼一次 88 星）；余额不足的卡整体淡化 + 「还差 N 颗」提示 + 兑换钮禁用。点「兑换」弹确认（见 ㉑），成功后 toast「兑换成功！宝物已放进星星宝藏箱」。底部三入口：星星记事本 / 星星提议板 / 星星宝藏箱。
5. **⑤ 星星记事本（/star-log）**：星星收支流水，最新在前；每条 = 印章图标（+ 橙金 / − 灰蓝）+ 事由 + 相对时间 + 金额。事由三类：答题得星、满分奖励、兑换：×××。
6. **⑥ 星星宝藏箱（/prizes）**：进行中的兑换券（兑了还没用）。每张券 = emoji + 名称 + 兑换日期 + 两操作：「用完了」（核销，弹确认 + 成功 toast）、「放弃」（弹确认，明示星星不退回）。核销与放弃都不动星星账本——券是已付款凭证。

## 核心流转二：提议沟通闭环（⑫ – ⑰）

孩子想要列表外的奖励时，走「提议板」协商，而不是直接兑换：

1. 任一方（⑫ 家长视角 / ⑮ 孩子视角）「新建提议」→ 填三字段（想换什么 / 花多少星星 / 说明文字）→ 保存。新建方自动「点头」。
2. 列表卡是**双阵营卡**：对方阵营恒在左、自己在右（卡通头像：孩子 = 发梢卷笑脸，家长 = 短发眼镜），各显示状态文案（还在考虑 / 刚刚提议 / 已修改提议 / 已点头）。
3. 双方各自表态：「同意 / 再想想」翻转本方开关；「改提议」进编辑，保存后对方状态重置回「还在考虑」。
4. 双方都点头 → 卡右上角出现绿色「已谈成」。**发布窗口**（每天 20:00–21:00）内，家长端出现「发布兑换项」按钮，点击后提议转为正式兑换项，出现在 ④ 兑换页列表——这就是孩子视角「让奖励上货架」的路径。
5. 任一方（仅家长视角有按钮）可「作废」提议，确认后转灰显「已作废」；已发布/已作废为终态。
6. 详情页（⑬/⑯）双视角同构：全字段 + 双方状态；差异 = 孩子视角无「作废」钮。列表页差异 = 家长视角点标题进详情，孩子视角无此入口。

## 家长端 · 管理面板（⑦ – ⑪）

- **⑦ 家长页（/parent）**：
  - 题库情况卡：一行三组（共 20 题 · 有 6 新题 · 最近答题 9月4日）。
  - 测试模式开关卡（页面常驻）：开启期间产生的星星流水会在关闭时全部撤销——给孩子演示/试玩用。
  - 四个大按钮：数据管理 / 流水管理 / 提议板 / 出题指令。
  - **设备与家庭区**（已配对的家长设备渲染）：设备名册（角色标签、本机标识、最后活跃、移除——移除 = 断云不擦本机数据）；家庭码（平时隐藏 ······，出示 6 位码给孩子设备配对，可重置）；快照回滚（近 30 天每日快照，回滚覆盖云端状态）。
  - 页尾「组件库」链接（开发者自检入口）。
- **⑧ 数据管理弹窗**：题库 + 兑换项的导出 / 导入（JSON 文件）。导入有二次确认：数据类弹「本次导入将写入 N 题」+ 双模式（导入并重置 / 导入并追加）。
- **⑨ 流水管理弹窗**：星星流水（含兑换项与提议）的导出 / 导入。导入确认弹「本次导入将写入兑换项 M 项 + 流水 K 条 + 提议 P 条」。
- **⑩ 出题指令页（/parent/question-prompt）**：填孩子水平、出题范围、题数 → 生成一段指令 → 复制粘贴给任意 AI（ChatGPT / 豆包）→ AI 产出的题库 JSON 经 ⑧ 导入。这是「题库从哪来」的主路径。
- **⑪ 配对页（/pair）**：新设备三步向导——输入家长设备出示的 6 位家庭码 → 给设备起名（默认「星星设备」）→ 选角色（家长设备 / 孩子设备，各自一句职责说明）→「配对」。第一台设备必须是家长设备；失败按类别给中文反馈可重试。

## 组件库与状态变体（⑱ – ㉑）

- **⑱ 组件库列表（/components）** + **⑲ 单组件展示（/components/:key，代表 star-button-standard）**：开发者自检页，平铺全部组件形态（按钮 variant × size 2×2 矩阵 + disabled）。产品语境中它不是用户功能，但展示了设计系统的最小单元。
- **⑳ 空态代表（兑换页空态）**：兑换列表为空 = 居中星星图 + 一句引导。其余空态（记事本 / 宝藏箱 / 提议板）同构。
- **㉑ 确认弹窗代表（兑换确认）**：正文（含价格与剩余数）+ 取消 / 确认双钮等宽。全 app 的确认弹窗（放弃答题 / 重新开始 / 作废提议 / 核销 / 放弃宝物 / 移除设备 / 重置家庭码 / 回滚快照）全部同构，仅文案与按钮文字不同。

## 不进快照的边缘态（拍板排除）

测试模式水印（孩子端「测试中」绯红胶带）、家长超能力卡（开发者自用后门）、兑换/核销成功 toast、hover/active 瞬时态、满分彩纸动效等瞬时/开发者状态不在 21 屏内；其视觉元素（弹窗、按钮、toast 容器）均已由在册屏幕覆盖。

## 快照的陈列口径（与真实实现的差异说明）

- 真实 app 每页锁一屏高、内容区内部滚动；快照为静态陈列，每屏按自然高度完整展开（min-height 660px 模拟一屏）。
- 弹窗（⑧⑨㉑）在真实实现中为全屏 fixed 蒙层 + 居中卡；快照中改为手机框内绝对定位陈列，视觉规格不变。
- 答题页陈列「已作答（答对）」瞬间态以同时呈现题卡、选项判分色、反馈条与可用的「下一题」。
- 流转关系以每屏标签与分区说明行中的编号箭头表达（① → ② → ③ …），无可点击导航、无 JS。
