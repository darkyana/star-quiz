# 迷你车库 · 美术接入可玩版

> 本文为美术接入轮记录。现行入口与协议以 [README.md](./README.md) 为准：游戏侧已支持协议 v1；通过 HTTP(S) 打开，不支持 file://；主 App 槽位仍未切换。

## 美术接入轮的授权范围与入口

基于游戏分支 `028c10a`。用户认可车辆和调整后的缓速带/跳台，要求“跳台略缩小，别的没什么问题，微调后进入下一步”。依照已约定的下一步，将这套美术接入真实可玩的三条路线，而不是继续只做静态赛段。

- **试玩入口：`index.html`**。首页选路线、轮胎和装置后开跑；跑完可以保留配置重玩或返回配车。
- **美术对照入口：`art-prototype.html`**，继续保留素材板与代表段，不再把它当作真正比赛。
- 当前内网服务的根目录就是本小游戏目录，`http://192.168.20.208:4173/` 或 `/index.html` 打开可玩版。IP/服务为当前环境信息，不是部署契约。
- 保持整个目录结构直接打开 `index.html` 也可运行。现在会请求相邻本地图片/脚本/CSS，旧记录中的“单文件、无资源请求”已经不适用。
- 这是独立美术接入试玩，不是正式付费版。仍无宿主、扣费/重玩授权、音频、持久化、自己的 Service Worker，也不合并 main。

## 本轮完成

1. **跳台微调**：美术代表段从 100×136 缩至 90×122.4，投影几何同时缩至 90%；方向、缓速带、车与其他素材不改。可玩版使用适配真实投影的紧凑尺寸，抬高端朝向同车道的对应缓速带。
2. **真实配车页**：沿用已评审的四张首页车图。选择轮胎/装置后同步主图、配置摘要和赛中用车；没有以固定主图冒充实时换装。
3. **三条实际路线**：渲染直接读取 `GarageModel.trackFor()` 的路面分段、障碍、全部 6 组跳台/缓速带与终点。没有把代表性构图复制成关卡，也没有替换关卡坐标。
4. **连续材质**：道路、沙地、碎石和桌面纹理由世界距离定位；轮廓、路沿和标线随模型道路滚动，避免纹理随屏幕游移。原路外减速保持，路沿只是低矮装饰，不是新增碰撞墙。
5. **接地与离地**：缓速带按模型带长与道路宽逐行采样，没有可绕开的路内侧缝；跳台高端锚定模型触发位置，坡道向来车方向延伸，按车道方向旋转并绘制高端较远、入口较短的投影。实际腾空、压缩、落地与装置效果使用模型状态驱动，不另设动画计时器。
6. **操控与结算**：保留按住左右、拖动、另一只手使用装置、暂停/继续、失焦暂停、冲线、保留配置重玩和返回配车。HUD 展示真实模型时间/速度/进度，结算展示本局真实计数，不用样板固定数字。
7. **素材就绪门**：18 份赛中资源与 4 张首页图加载完成后才能开局；加载期间不开始计时。图片失败会说明情况并允许重试，不在一片空白里开跑。该就绪门不等于宿主 start 授权。
8. **碰障美术反馈**：根据模型 hits 增量短暂显示柔和气圈与“轻轻碰到，继续开”，不改减速强度，不扣命、不抖动镜头。

## 保持不变的部分

`index.html` 中整个 `GarageModel` script 与 `028c10a` **逐字节相同**；开发工具对变更前后 48 组完整模拟结果做逐字段比较。

- 三条固定 1800 单位路线及全部障碍/跳台坐标。
- 前 12 秒原速，12–50 秒 smoothstep 提速，50 秒后 +28%。
- 两种轮胎路面差异、操控增益、碰障损速、路外减速、缓速带限速。
- 借台与主动弹跳共用腾空规则，空中经过跳台不续飞。
- `motion()`、`bandCue()`、固定步长循环、转向/拖动输入公式不改。
- 首页原图、四配置主图、四配置赛中车和整套独立素材字节不改。本轮是绘制与界面接入，不再重新生成素材。

### 投影变化的明确说明

真实 Canvas 路面映射为 `X = width/2 + normalizedX × width/2`，路沿对应模型路内范围 ±0.55；相较旧功能原型道路更宽。纵向仍是 160 游戏单位视野，小车基线仍为视区高度的 76%。这是绘制投影，不是更改模型的碰撞距离或操作增益；相同归一化状态有更大的横向像素位移，需要真人确认实际视觉手感。

缓速带逐行贴合实际模型路段，路内没有侧缝；路外仍允许原来的低速绕行。跳台、障碍图片的绘制轮廓不是新碰撞体。真实赛道尺寸受视区和模型映射约束，不以静态样板物件的像素大小重定义关卡。

## 代码与设计边界

- `index.html`：三个玩家视图、原模型与流程、资源就绪提示、加载/重试和调用绘制模块。
- `playable-art.js`：资源加载/缓存、世界坐标绘制、独立效果层。接收模型和当前状态，不调用 model.step/activate，不改 state，不碰授权或存储。公开 `lastFrame` 仅供浏览器核对渲染覆盖，不驱动玩法。
- `playable-art.css`：小游戏私有外观，沿用评审的纸白、深青、珊瑚橙与鼠尾草绿。配置卡、素材状态、HUD、控制区、结算卡均为原生组件；不修改宿主令牌/组件/App.vue。
- `track-kit-preview.js`：仅做 10% 跳台/投影尺寸调整。静态美术入口继续与真实比赛分开。
- `tools/mini-garage-art/verify-playable.cjs`：模型/浏览器回归工具；Playwright 属于隔离的离线检查依赖，不加入产品 package.json。

材质纹理缓存按尺寸最多保留 16 项；画布 DPR 上限 2。纹理和图片在准备阶段加载，动画只读同一模型时间，因此暂停后冻结。碎石继续采用很轻的悬挂脉冲、没有摇头；整车是单张配置精灵，轻微压缩作用于精灵而非独立车轮骨骼，仍需真机观感评审。

## 已做的检查

运行方式（游戏 worktree 根目录，PREVIEW_URL 使用已经存在的服务，不会另起服务器）：

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright \
PREVIEW_URL='http://192.168.20.208:4173/index.html?review=art-play-01' \
node tools/mini-garage-art/verify-playable.cjs
```

未传 PREVIEW_URL 时使用 `file://`，跳过只能通过 HTTP 拦截验证的加载失败分支；始终包含单独的 file:// 启动检查。

通过的检查：

- 冻结模型逐字节比较；三路线 × 四配置 × 四种策略共 48 组完整模拟，结果与接入前完全一致；motion/bandCue 保持相同。
- 浏览器实际选择全部 12 种路线/配置组合，首页主图与赛中精灵一致。
- 在实际模型的每个路面分段、每个障碍、每组跳台和缓速带附近绘制并核对覆盖，直道快线没有新增跳台或缓速带。
- CDP 两根真实触摸指针同时转向与弹跳，松手恢复；拖动/释放；暂停状态与 HTTP Canvas 像素保持不变；继续、失焦暂停正常。
- 冲线进入结算；重玩重建状态、清空时间/碰障/装置冷却，并保留配置；返回配车保留选择而不保留未完成一局。
- 320×568、390×844、844×390、1024×768：配车/结算无横向溢出，驾驶页无需纵向滚动，控制按钮在屏内。iPad 单列最大宽度 460。
- 全部图片加载失败场景中模拟一张跳台图片请求失败：开局禁用、直接调用开局也不创建状态；重试成功后可进入比赛。
- 减少动态偏好、独立 file:// 启动、脚本语法和 diff 空白检查。
- 桌面 Chrome 的 150 次同步 render+draw 提交测试在本机中位数约 0.1ms、P95 约 0.3ms；**不包含完整 GPU 呈现成本，不是 iPhone FPS 验收**。

截图位于 `art-review/play-*.png`：首页、三路线、沙地、腾空和结算。赛道/腾空图由工具定位到指定检查状态；结算图来自完整的模型策略模拟，不是真人比赛成绩，也不是手填的成绩。测试只发生在独立浏览器内存，不写入用户记录或生产存储。

## 接下来请真人试玩

重点：连续滚动后是否清楚、跳台缩小后是否仍好辨认、真正起跳和落地是否自然、两指操控是否舒服、后半程提速是否仍看得清障碍。视觉投影更宽，但没有改动玩法参数；如果手感需要微调，应单独记录并确认，不偷偷修改冻结规则。
