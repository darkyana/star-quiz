# 惊喜题库出题 Prompt

给外部 AI(豆包 / ChatGPT / Claude 等)用的中文问答出题模板。生成结果由人工核对事实后,整理成现役题集的 `set.json` 放进 `public/trivia/current/`(换题集 = 整夹替换 + 旧夹归档,全程零代码,见 `public/trivia/archive/README.md`)。

## 用法

1. 复制下面整段;
2. 把 `<大类>` / `<分册>` 替换成题集名称(如「百科 / 常识」;名称与主题解耦,只作调度范围键);
3. 把 `<介绍>` 替换成孩子侧介绍弹窗文案(1–2 句,见下方输出格式);
4. 把 `<主题>` 替换成具体主题(如「恐龙」「太空」「人体」);
5. 把 `<数量>` 替换成想要的数量(建议 10–30 道一批);
6. 把 `<起始号>` 替换成题目 id 起始号——**占 9 号段(9xxxxx)且不得与现役/归档任何题重复**,从「现役 set.json 最大序号 + 1」起顺延(如现役用到 900094,新题从 900095 起);
7. 贴给外部 AI;
8. 收到输出后人工核对事实,按下方「落库步骤」整理进 set.json。

## Prompt

```
你是一位面向小学生的科普问答出题老师,现在需要为一个家庭答题小程序生成一批「惊喜问答」题目。

【题集名称】
大类:<大类>  ← 必填,如:百科
分册:<分册>  ← 必填,如:常识
介绍:<介绍>  ← 必填,1–2 句孩子侧介绍文案,如「欢迎来到惊喜题库!……准备好了吗?马上开始!」

【主题】
<主题>  ← 必填,例如:恐龙、太空、人体、世界之最、海洋动物、中国历史朝代…

【数量】
<数量> 道  ← 建议 10–30 道一批

【起始号】
题目 id 从 <起始号> 起连续顺延(6 位数字字符串,占 9xxxxx 段),如 900095、900096、900097…

【题目规格】
- 每道题为「4 选 1」单选题,适合 7–12 岁儿童作答;
- id:从起始号起每题 +1 顺延,6 位数字字符串;
- type:固定 "trivia";
- 题干(prompt):用 1–2 句简洁中文提问,长度不超过 30 字;遇到必用专有名词可保留英文/拉丁名,如「霸王龙(Tyrannosaurus rex)」;
- 选项(options):恰好 4 个,均为字符串,长度尽量接近,均为儿童可理解的中文表达;选项顺序无意义,不要按答案顺序排;
- 正确答案索引(answerIndex):0–3,指向正确选项的位置,且正确选项必须真实准确;
- 不要 category / book / wordId 等其他字段(由题集头部统一承载);
- 选项不要出现「以上都不对」「以上都对」「不知道」等万能答案;
- 不要出争议题、未定论题、过度地域性题(如国旗首都,孩子语境外不必考)。

【输出格式 · 严格遵循】
请分别输出两段,不要 Markdown 代码块包裹、不要注释:

第一段是题集 JSON(将直接作为 set.json 使用),头部为元数据、随后是题目数组:

{
  "category": "<大类>",
  "book": "<分册>",
  "intro": "<介绍>",
  "questions": [
    { "id": "<起始号>", "type": "trivia", "prompt": "题干中文文本?", "options": ["选项A", "选项B", "选项C", "选项D"], "answerIndex": 2 },
    ...
  ]
}

第二段是核对稿(仅供老师校对,绝不进入 set.json),逐题给一句话解释:

- <id> 「prompt」: 正确答案是「…」,依据一句话;
- …

【自检要求】
生成完毕后,你必须自查:
1) 每道题 options 长度都恰好为 4;
2) answerIndex 都在 0–3 区间,且 options[answerIndex] 确实是事实正确的选项;
3) id 从起始号起连续顺延、无一重复、全部为 9xxxxx 段 6 位数字字符串;
4) 题目之间不要重复主题角度(同一批内不要重复问同一件事);
5) 难度梯度均衡:简单(常识直观)、中等(需要知道)、进阶(需要记准细节)各占约 1/3;
6) 把所有题目的「主题覆盖范围」和「难度分布」以一句话附在最后,供我审稿时一眼看出盲区。
```

## 落库步骤

把外部 AI 返回的**第一段题集 JSON**落成现役题集(第二段核对稿不入库):

1. **归档旧题集**:把 `public/trivia/current/` 整夹移入 `public/trivia/archive/<slug>/`,id 不回收(归档序号永不复用,新题永远从现役最大序号 + 1 续号);
2. **上架新题集**:新建 `public/trivia/current/`,放入整理好的 `set.json` 与贴纸图(`icon.svg` + `icon.png`,沿用 `docs/design/surprise-sticker` 三色归档之一,无需改代码);
3. **核对头部字段**:category / book / intro 与出题设定一致(贴纸图文件名固定为 `icon.svg`/`icon.png`,代码经 `TRIVIA_SET_SLOT` 硬编码读取,set.json 不携带 icon 字段);题目条目只含 `id / type / prompt / options / answerIndex` 五个字段;
4. **（可选）人工补得星规则**:需要本轮惊喜产星时,在 `set.json` 头部补 `starRule`——`{ minAccuracy, stars }` 数组(正确率下限 ∈ (0,1] → 星数),形状与非法整集拒绝语义见 `public/trivia/archive/README.md`;**不含此字段 = 纯玩、惊喜轮不产星**。档位由人定,不要让外部 AI 生成此字段(prompt 输出形状刻意不含它);
5. **不要复制 explain/核对稿**——仅作人工核对对照用,任何解释性内容都不得出现在 set.json 里;
6. **去掉 Markdown 代码块包裹**——外部 AI 有时会用 ```json … ``` 包起来,落库前要去掉;
7. **跑验收测试**:`npx vitest run src/data/__tests__/trivia-set.test.ts`(题量 ≥3、id 全 9 号段且唯一、题目形状、名称一致的人工安全网),建议再跑全套 `npx vitest run`。

## 设计取舍说明

- **输出即 set.json**:题集载体是 repo 静态资产槽位(对齐 public/games 的做法),App 冷启动预热加载校验后并入惊喜调度池;让外部 AI 直接按 set.json 形状输出,人工只做核对与归档/上架搬夹,全程零代码。
- **id 由起始号顺延**:9 号段是惊喜题库归属的唯一判定依据(ADR 0014,来源即身份),且与用户题池「现有最大序号 + 1」永不冲突;起始号在用法第 6 步由人给定,AI 只负责顺延。
- **category / book 放头部**:题库两层归属由题集元数据统一承载,题目条目不携带,避免两处漂移;名称与主题解耦,换主题不改代码常量。
- **explain 单独输出供人工核对**:解释文字单独成段,永远不进 set.json——题库只存孩子可见的题目数据,核对稿留在出题对话里。
- **不加 wordId**:惊喜题天然无词归属、不进近期已测词——这条直接写进 prompt 的「规格」里更稳。
- **starRule 由人工落库时补(#289)**:得星档位是产品决策,不该由外部 AI 自行发明——prompt 输出形状刻意不含 `starRule`,需要产星时人工按契约补在头部;缺省即纯玩。
- **不出「pic2en(图译英)」题**:该题型尚未启用,需要图资产,外部 AI 单独生成不合契约,模板里默认排除。
- **难度梯度靠「自检要求」兜底**:惊喜题库面向孩子,过度专有名词会导致未玩过的孩子无法参与;均衡要求写在自检里,提示词末尾再要一句话分布概览,便于人工审稿时一眼看出盲区。
