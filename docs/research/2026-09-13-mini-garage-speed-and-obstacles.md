# 迷你车库：前进速度与障碍节奏调研

> 2026-09-13；状态：研究与试调建议，未修改游戏。针对孩子反馈“车太慢，不刺激”。

## 结论

不应寻找一个可以直接抄的“行业标准车速”。更有用的调参尺度是：**每秒滚过多少画面、障碍出现后多久到达玩家、多久需要做一次操作，以及操作是否来得及完成**。一手实现与证据见[来源笔记](mini-garage-speed-primary-sources.md)。其中的具体产品参数不是跨游戏标准，更不是儿童反应时间标准。

对本游戏，建议先试“明显提速、缩短热身、减少长时间爬行”，暂不同时大幅加密障碍；再按操作时间检查三条路线。只调整仪表盘上的 km/h 不会改变体感。

## 一手案例支持什么

- **Chromium 小恐龙（固定 74.0.3719.3 版本）**：开局留 3 秒缓冲，逐渐提速并设上限，部分障碍达到速度阈值才出现；最小间距采用 `round(障碍宽度 × speed + 类型 minGap × 0.6)`，再在最小值到 1.5 倍之间随机。说明速度、间距、障碍类型需要联动；但间距增长不代表反应时间不变。该源码 speed=6→13 是 60 FPS 基准参数，不能当作 6→13 px/s 照抄。[固定版本源码](https://chromium.googlesource.com/chromium/src/+/refs/tags/74.0.3719.3/components/neterror/resources/offline.js)
- **Godot 官方 Dodge the Creeps**：玩家 400 px/s、敌人 150–250 px/s，每 0.5 秒生成敌人，开局等待 2 秒。这是固定屏幕躲避教学示例，说明也可以独立控制移动速度与时间生成频率；不是自动前进游戏的标准，也没有保证随机组合总是可解。[玩家源码](https://raw.githubusercontent.com/godotengine/godot-demo-projects/master/2d/dodge_the_creeps/player.gd)、[生成源码](https://raw.githubusercontent.com/godotengine/godot-demo-projects/master/2d/dodge_the_creeps/main.gd)、[官方教程](https://docs.godotengine.org/en/4.5/getting_started/first_2d_game/05.the_main_game_scene.html)
- **Xbox 无障碍指南 108**：支持按能力提供难度选择和分项调节，提到年轻玩家可能需要较低难度；没有给儿童通用速度或反应秒数。[官方指南](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/108)

因此有可以借鉴的成熟实现方法，但这份样本不足以声称某个公式是“全行业统一常规”。本游戏最适合借鉴小恐龙的渐进节奏与速度／间距联动，再补上连续横移、软地抓地与跳台组合的可达性检查。

## 1. 当前运行实现

入口以 [GAME_SLOT](../../src/data/playable-games.ts#L4-L12) 为准，指向 `public/games/mini-garage-prototype/index.html`；交付 README 中“未切换槽位”等历史说明不代表当前槽位状态。

参数来自 [GarageModel](../../public/games/mini-garage-prototype/index.html#L62-L157)，投影来自 [GarageArt.projection](../../public/games/mini-garage-prototype/playable-art.js#L23-L25)。以下速度均为游戏世界单位/秒，不是真实米/秒。界面虽以速度乘 3.6 显示 km/h，却不能由此判定运动观感。

| 项目 | 当前值 | 对节奏的影响 |
|---|---|---|
| 公路胎／硬地基础速度 | 25 | 每秒仅滚过 0.156 个画布高度 |
| 越野胎／硬地基础速度 | 21 | 比公路胎更慢 |
| 公路胎／非硬地基础速度 | 13 | 明显变慢，横移抓地也变弱 |
| 越野胎／非硬地基础速度 | 21.5 | 更适合混合赛道 |
| 难度增长 | 前 12 秒倍率 1；到第 50 秒平滑升到 1.28，随后不再增加 | 加速起步较晚，最终只增加 28% |
| 公路胎硬地成熟速度 | 32 | 每秒 0.2 个画布高度 |
| 加速装置 | 目标速度 ×1.6，持续 2 秒，冷却 7 秒 | 当前成熟硬地目标最高 51.2，实际速度平滑逼近 |
| 前方视野 | 160 × 76% = 121.6 世界单位 | 障碍中心从画布上沿到车辆基线约 4.86 秒（25）／3.8 秒（32） |
| 直道障碍 | 15 个；间距 100–120，平均 110 | 稳态下约每 4–4.8 秒（25）或 3.13–3.75 秒（32）经过一个 |
| 碎石／工坊障碍 | 各 13 个；间距分别 72–268／62–260 | 同时存在紧密组合和长空段，不能用一个平均密度概括 |
| 碰障 | 速度立即变为原来的 28%，再向目标恢复 | 不判负，但瞬间损失 72% 速度 |
| 缓速带 | 长 14，在道路内着地时速度上限 4 | 全程着地约需 3.5 秒；工坊有 4 条 |
| 路外 | 着地目标速度 ×0.48 | 误操作也可能让孩子持续觉得慢 |

视野时间是匀速、障碍中心到车辆基线的几何估算，不是测得的儿童反应时间；实际初次可辨认时刻还受精灵大小、屏幕和遮挡影响。提速过程应使用累计距离而非假定全程匀速。

## 2. 应用时采用的调参方法

以下公式是本次对源码案例的工程归纳，不是某组织发布的规范。

### 先规定“秒”，再换算距离

- 画面速度：`屏高/秒 = 世界速度 / 160`。比任意 px/s 或界面 km/h 更方便跨设备比较。
- 预览时间：`T_preview ≈ 可辨认的前视距离 / 速度`。
- 相邻障碍经过间隔：`T_gap ≈ 纵向间距 / 速度`；反推布局则是 `间距 ≈ 速度 × 目标间隔`。
- 若速度变化明显：使用 `距离 = ∫v(t)dt`；若以后改生成器，按实际速度和可用反应窗口决定生成位置与间距。
- 想“更快但不更难”，同步扩大视野／间距；想“更快也更紧张”，允许窗口适度缩短，但须保住可操作下限。二者不要混为一谈。

### 保证连续操作来得及

不是“每一排都有空隙”就算公平；玩家必须从前一处安全位置到得了后一处。

当前是连续横移，不是固定车道：[step](../../public/games/mini-garage-prototype/index.html#L104-L107) 的横移上限为 `0.9 × grip`。以从 -0.3 移到 +0.3 的 0.6 归一化距离为例，忽略道路弯曲和扰动时，满幅按键最短耗时：

- 公路胎硬地：0.6 / 0.9 ≈ **0.67 秒**。
- 公路胎非硬地：0.6 / (0.9 × 0.48) ≈ **1.39 秒**。
- 越野胎：0.6 / (0.9 × 0.86) ≈ **0.78 秒**。

还要加辨认／决策时间、拖动控制的渐近收敛和余量；这些数值只是运动学下限。建议按 `可用时间 ≥ 决策时间 + 横移时间 + 安全余量` 验证，不能拿成人实验室简单反应时间当儿童实玩门槛。

重点复查工坊 z=602 障碍到 z=682 跳台的左右切换（相差 80，障碍在 +0.3、跳台在 +0.3，但避障路径可能在另一侧），以及全部“障碍→跳台→缓速带”组合。在速度 80 时，80 单位只剩 1 秒，已可能小于公路胎在软地上的大幅横移耗时。

### 把速度感与惩罚强度分开

碰撞仍只减速、不判负，可以保留。缓速带长时间维持速度 4，则直接抵消提速获得的畅快感。后续应单独比较“短促减速后恢复”与当前“整个带内持续爬行”，同时保留对准跳台、选择轮胎的收益。这里是待试玩建议，不是已确定的新规则。

## 3. 建议的第一轮对照方案（未实施）

只先在直道快线验证，避免软地、跳台、缓速带混入，无法知道改善来自哪里。

| 项目 | 当前公路胎硬地 | 候选试调值 |
|---|---|---|
| 基础速度 | 25 | **40**（+60%） |
| 热身与增长 | 前 12 秒不提速，50 秒满倍率 | 前 **4 秒**热身，到 **25 秒**平滑达到满速 |
| 正常成熟速度 | 32 | **50**（基础倍率 1.25） |
| 前视时间 | 4.86 → 3.8 秒 | 3.04 → 2.43 秒 |
| 障碍间距 | 100–120 | 第一轮不改；对应间隔 2.5–3 → 2–2.4 秒 |
| 加速倍率 | 1.6 | 第一轮建议试 **1.3**；成熟目标 65，前视约 1.87 秒，避免与基础提速相乘过猛 |

**这些是基于现有尺度提出的试验起点，不是业界推荐值，也未验证适合孩子。** 基础速度 40→50 比现状明显快，但正常前视仍超过两秒，适合作为首轮比较而不是一步拉到极限。

一次只验证一个主要因素：先基础速度／增长曲线（对照时不主动用装置），再测加速装置，最后才调减速惩罚与复杂路线。没有必要马上重写成无限跑酷或随机生成器。

### 必须一起考虑的后果

1. **一局会变短**：赛道固定 1800 单位；按候选速度粗估直道无失误约 39 秒（含起步及增长），不是当前约 64 秒。保持局长需要另行扩赛道和布局；不自动改价格／扣星规则。若后续障碍超过 31 个，当前位掩码记录方式也需复核。
2. **跳跃相对变强**：固定腾空 1.8 秒，近似覆盖距离随速度增加；现状速度 25 时约 45 单位、50 时约 90，不能只测“没撞”，还要检查是否轻易跳过多组挑战。
3. **软地横移可能跟不上**：前进提速不自动改善 grip；必须按轮胎、路面、加速态分别验证路线可达性。
4. **小步长不是玩法保证**：现有前后 z 跨越判定和 1/120 子步有助于避免跳过障碍事件，但不能证明高速下组合可解、触摸手感良好。
5. **新参数需更新行为测试**：后续实施时增加速度曲线、最短窗口、加速态组合、跳台落点等验证，不能只沿用历史冻结基线。

## 4. 怎样决定最终值

- 在实际手机／iPad 上让孩子比较旧版与候选版，不展示“更刺激”等引导性标签；问“哪个更想再玩，哪里太慢／来不及”。
- 记录本次试玩的碰撞、路外时间、缓速时间、通关时长及孩子主观反馈；不为调参新增云端追踪。
- 首先要求正常速度更畅快、没有不可解的连续组合；再检查加速态仍能提前辨认。
- 三路线 × 两轮胎 × 两装置均需回归；按键和触摸分别测，自动策略只能辅助。
- 年龄、熟练度和设备尚未明确，不把任何窗口宣称为“适合所有儿童”。
