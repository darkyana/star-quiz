# 躲避／无尽跑酷：速度与障碍的一手证据

> 范围：仅调研，不修改游戏；不评价当前游戏参数。区分实现事实、平台指南与本文工程建议。

## 结论

- **本次一手资料未提供统一的前进速度、障碍间距或儿童适用 px/s 标准。** 实现可借鉴的是速度与生成机制联动、开局缓冲、难度分级；两个案例不足以证明全行业采用同一方法。
- 比较速度应先统一逻辑坐标、可见距离和相对运动，再比较**从可辨认到碰撞的时间**，不能直接照搬别的游戏 px/s。
- 加速时增大障碍距离不一定保住操作时间；换道游戏还需要连续路径可达性验证，不能只保证“每排有一个空车道”。

## 1. 实现案例 A：Chromium Dinosaur Runner

第一方固定版本：[Chromium 74.0.3719.3 / offline.js][C]（下列行号均来自此版本；不是对现行 Chrome 的断言）。

| 已核实事实 | 含义／边界 |
|---|---|
| `FPS=60`，`SPEED=6`，`MAX_SPEED=13`；障碍更新 `x -= floor(speed*FPS/1000*deltaTime)`（约 L90–136、L1481） | 6、13 是以 60 FPS 为基准的速度参数，换算约 **360、780 逻辑 px/s**，不是 6、13 px/s；实际逐帧取整有偏差，不能等同物理屏幕像素。 |
| 默认宽 600；窄屏 `min(speed, speed*width/600*1.2)`（L340–350） | 该实现会按视野宽度调整速度，说明仅报绝对速度不完整；并非严格保持相同预警时间。 |
| `minGap=round(obstacleWidth*speed+type.minGap*0.6)`；`maxGap=round(minGap*1.5)`；两者之间随机（L1508–1512） | 间距同时依赖速度与障碍宽度。上一障碍右缘加 gap 移入视野后才生成下一只（L2869–2874）；gap 是生成空间约束，不是保证玩家反应时间。 |
| `ACCELERATION=0.001`，低于速度上限时每次更新累加；`CLEAR_TIME=3000ms`；翼龙 `minSpeed=8.5`（L554、577–578、1582） | 开局缓冲、逐渐加速、达到阈值才引入新障碍。此版本加速量按更新次数累加，不能误写成每秒加 0.001，也不宜照抄其帧率依赖。 |

**公式的实际后果（本文换算，不是原作者调参建议）**：单个小仙人掌宽 17、类型 `minGap=120`。速度参数 6 时最小 gap=174，13 时=293；分别除以约 360、780 px/s，空间间隙对应时间约 **0.48s→0.38s**。所以“速度越高、间距越大”仍可逐渐变难。这也不等于完整两次动作间隔：还要计入障碍长度、玩家碰撞体与动作恢复。

## 2. 实现案例 B：Godot 官方 Dodge the Creeps

这是**固定屏幕内持续生存的躲避教学示例**，不是自动前进、三轨换道跑酷。官方源码说明与参数：[README][G0]、[player.gd][G1]、[main.gd][G2]；生成定时参数另有[官方 4.5 教程][G3]。

- 玩家 `speed=400`，注释单位为 pixels/sec；`velocity=normalized(input)*speed`，`position += velocity*delta`。归一化避免斜向输入额外提速。[G1]
- 每只敌人速度 `randf_range(150,250)`，速度向量按出生边界方向加 `[-π/4,+π/4]` 随机偏转；出生点随机。[G2]
- `MobTimer=0.5s`，`StartTimer=2s`：开局等待，然后按固定时间生成敌人。[G3]

**能证明**：第一方示例可以用“每秒位移＋时间生成器”设置持续躲避，而不必使用 Dino 的速度相关空间 gap。**不能证明**：这些数值适合儿童、适合跑酷，或固定随机生成自动保证永远有解；上述示例也不是渐进提速的证据。源码链接为浮动 master，教程链接固定 4.5，复用时应再次核对版本。

## 3. 面向换道跑酷的工程推导（不是行业标准）

以下是运动学与可达性约束，**不是上述两款游戏提供的换道公式**。

1. **先算可用预警时间。** `D` 为障碍第一次可辨认时到首次碰撞边界的有效距离，`v_rel` 为接近速度；恒速时 `TTC=D/v_rel`。不要用整个画布高度代替 D，也不要把刚进入透视远端但无法辨认算作有效预警。加速时解 `∫v_rel(t)dt=D`；匀加速即 `D=v₀T+½aT²`。屏幕投影速度不能直接当世界速度。
2. **给操作留预算。** 简化条件：`TTC ≥ 识别/决策时间 + 输入延迟 + 所需换道时间 + 安全余量`。匀速横移可用 `换道时间=横向距离/横向速度`；缓动/固定动画应测到碰撞体真正脱离危险区域的耗时。跨两道、输入冷却、不能打断动作都要单独计算。
3. **用时间预算反推间距。** 恒速下，若相邻障碍的有效净空距离为 g，所需安全操作时间为 B，则 `g ≥ v_rel*B`；若使用前缘到前缘距离，还须加上前一危险段长度及碰撞体扫掠余量。变速用积分距离或最高可能速度保守估计；加速道具不能绕过此校验。
4. **检查连续可解路径。** 以“车道、时间、动作状态”为节点；仅在全过程不碰撞且耗时允许时连边。生成后检查从当前可达状态能否穿过前方多排障碍；不可达则重采样或留空。各排分别有空位，仍可能要求来不及完成的左右连切；随机 gap 不是可解性证明。
5. **渐进难度分轴调整。** 可分别调整速度上限、操作时间预算、障碍组合与换道次数；建议先引入单一障碍，再引入组合，避免同时加速、加密和增加跨道要求。实现应按 `delta` 或明确固定步长推进，而非依赖渲染帧数。

**仅作试验起点的建议值**：例如希望可辨认后的 TTC 为 3s，有效前视距离为 120 个逻辑单位，则恒速上限初值为 `120/3=40单位/s`。这里的 3s 是待试玩验证的设计假设，**不是儿童反应时间结论，也不是行业标准**；若实测动作预算更长或障碍难辨，应增大 TTC。

## 4. 儿童适用性：证据到哪里为止

[Microsoft Xbox Accessibility Guideline 108][X] 明确指出难度取决于玩家能力与游戏障碍的关系，年轻玩家、休闲玩家及新手可能需要较低难度；建议提供难度预设、分项调节、辅助与暂停。它是**第一方无障碍设计指南**，不是跑酷速度规范，也没有给出儿童年龄对应的反应秒数。

因此不能从 Dino 的普及、Godot 的教学用途或成人简单反应测试推出“某速度适合小学生”。建议按目标年龄、游戏经验和实际触屏设备做试玩，记录首次障碍成功率、误操作、连续换道失败、碰撞前可见时间及孩子的挫败反馈；保留可选低速／宽间距、练习与暂停。此处是验证方案，不是已获得儿童实验支持的参数。
