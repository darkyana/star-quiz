# Mission: 用 star-quiz 评审 App 的 module 设计

## Why
用户希望在 AI 提出架构方案时，能够追问、判断、拍板，而不是只能接受。用本仓库的真实业务与代码作为证据，理解 module 的职责、interface 和 seam，逐步判断新增、独立、合并与做深 module 的取舍。

## Success looks like
- 能用业务语言解释一条真实操作链中，各 module 负责什么、谁调用谁。
- 面对拆分方案，能问出它隐藏什么复杂性、调用者还必须知道什么。
- 能用具体变化场景比较拆分前后，而不是按文件大小或 module 数量拍板。
- 能分清代码组织上的独立与独立部署；能要求 AI 提供 seam 的实际变化需求和测试证据。

## Constraints
- 用户明确选择：目标 A（评审 AI 方案）；基础 A（基本不读代码）。
- 全中文、业务动作与图解先行，不要求掌握语法。
- 每课约 5–10 分钟，只练一个判断；回答后再记录理解证据。
- 本目录是独立教学工作区，沿用现有教学样式；不覆盖 Cloudflare 课程，不修改 App。

## Out of scope
- 当前阶段不以亲手编码、重构、背诵架构模式为目标。
