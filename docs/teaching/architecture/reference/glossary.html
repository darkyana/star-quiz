Module：有对外约定，也有内部做法

不是文件夹的同义词。一个函数、一组协作代码，都可以构成 module。先说清观察尺度，再讨论拆合。

Interface：使用它必须知道的一切

包括交什么资料、得到什么结果、有哪些失败、要先做什么、会改变什么。不是屏幕界面，也不只是参数列表。

Implementation：内部怎样完成工作

理想情况下，调用者不用亲自安排其中的细节；但内部效果和限制仍须由 interface 清楚交代。

Depth：学会少量约定，能办多少事

深 module 让调用者少操心、得到更多能力。不是文件越长越深，也不是把无关工作全塞一起。

遇到“应该拆一个 module”时问

  1. 谁会使用它？使用者交什么、得到什么？
  2. 使用者因此不必再知道哪条规则、哪种细节？
  3. 举一个具体变化：拆之前改哪里，拆之后改哪里？
  4. 新增了哪些传话、顺序要求和失败处理成本？

若只是“文件更短”“以后可能用到”，理由还不够；若规则不再散落、调用者真的省事，才有实质收益。拆合仍须结合需求与测试判断。

后续课再展开

Seam（接缝）
能够不修改该处代码就改变行为的位置；不是任意两个文件相邻的地方。
Adapter
在某个 seam 满足 interface 的具体实现角色。
Leverage
调用者学会少量约定所获得的能力。
Locality
让相关知识、修改和验证集中，而不是散落各处。
