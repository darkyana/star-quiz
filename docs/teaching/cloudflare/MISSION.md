# Mission: Cloudflare 部署拼图基础概念

## Why

老板是产品负责人，零部署经验——历次部署都由 AI 一步步带着操作。原话使命：「把这些步骤里面包含的基本常识教给我——这些工具的性质、它们管什么、一些常见的概念——让我有一些基础概念，能够做基础判断。」换来的具体改变：下次 AI 给出部署步骤或方案时，能看懂、能追问、能拍板，而不是只能点头。

## Success looks like

- 看 AI 给的部署步骤时，能说出每一步在动部署拼图里的哪一块（DNS？边缘？托管？数据库？）。
- 应用出问题时，能做分层判断：大概是 DNS 层、Cloudflare 边缘层、源站/托管层，还是应用本身的问题，并把线索交给对的人（AI）。
- 能评估一个部署方案是否合理，例如「star_quest 为什么用 Pages 托管静态壳、将来为什么用 Workers + D1 做同步」，而不是只有「照做」一个选项。
- 看到 Cloudflare 面板或文档里的常见词（Pages、Workers、D1、路由、自定义域……）不再陌生，知道去哪张表查。

## Constraints

- 全中文授课；读者零部署经验，不预设任何云服务知识。
- 目标是**判断力**，不是运维技能——不追求独立完成部署操作。
- 教材锚定真实拼图：现役部署（GitHub + Cloudflare Pages + 自定义域名）与已锁技术栈（ADR 0003：Pages 托管 + Workers 计算 + D1 + Cron 每日快照），不教抽象云知识。
- 课程形态：短课（5–10 分钟单课）+ 小测 + 术语表，符合仓库 teach 技能的形态约定。
- 时间态口径：分清「现役」（Pages 链路）与「将来」（Worker/D1/Cron 属 P0 #119 未落），教学不混淆。

## Out of scope

- 亲手运维操作教程——那是 AI 带着做的，不是本工作区的目标。
- 锁定栈之外的云服务横向对比（AWS/GCP 等）。
- Kubernetes、容器编排等大厂抽象。
