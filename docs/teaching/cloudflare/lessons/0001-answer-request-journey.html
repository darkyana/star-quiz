第 1 课：一次答题请求的旅行

约 5–10 分钟 · 单一收获：一张站点地图 · 生词查 术语表

这一课只教你一件事：孩子点开应用到页面出现（以及将来的数据同步），路上每一站是谁、Cloudflare 各产品各管哪一段。学完你手里就有一张地图——以后 AI 说「我们改一下 DNS 记录」或「在 Worker 里加个门禁」，你能立刻定位它在动哪块拼图。

先交代一个容易误解的事实：答题本身不出网。star_quest 是本地优先的应用，孩子每一题的对错、每一颗星星，都记在设备本地的 localStorage 里，断网也照常答题。那联网是为了什么？取「应用壳」——应用的页面和代码文件。这条路，才是今天要走的路。

现在这条路：取应用壳 现役

孩子 iPad 主屏上的图标，本质是一个指向你域名的入口。点开图标，设备要去「取应用文件」，于是上路：

  1. 孩子的 iPad（出发点）
    发起者：点开主屏图标，设备准备向你的自定义域名要应用文件
  2. DNS（指路牌）
    管「翻译域名」：把你的域名翻译成 IP 地址，好知道该把请求发给谁（DNS 是什么）
  3. Cloudflare 边缘（大陆可达的功臣）
    管「就近递货」：CDN 缓存 + 代理一体——文件在边缘有缓存就直接给，没有才回源去拿（CDN 是什么）
  4. Cloudflare Pages（仓库兼发货员）
    管「吐静态文件」：GitHub 仓库 star-quiz 一 push 到 main，Pages 就自动构建发布，边缘从这里进货（Pages 文档）
  5. 回到 iPad 本地（应用壳跑起来）
    管「答题与记账」：应用在本地运行，星星流水写进 localStorage，不再出网

一句话版：点开图标 → DNS 指路 → Cloudflare 边缘递货 → Pages 是仓库 → 壳在本地跑。这条「客户端—服务器一来一回」的路是所有网页的底模，MDN 的 How the web works 把它讲得最全，推荐作为本课的第一手读物。

将来多出的岔路：数据同步 将来（P0 未落）

现在这条路只走「取壳」。等 P0 实施票落地，会在同一个域名下多出一条岔路：同步请求——多设备各自的答题记录、星星流水要汇到云端（云端做汇合点而非真相源，离线照常可用），于是路上多几站：

  1. 同步请求（从应用里发出）
    管「带账上路」：写入即推增量、冷启动全量拉合，走的还是你的域名
  2. 路由（Routes，分岔口）
    管「分拣」：按请求长什么样，把同步请求从取文件的请求里分出来，送进 Worker（路由文档）
  3. Worker（门卫兼账房）
    管「验票和合并」：验家庭码门禁，算各设备记录怎么合并成一份账（Workers 文档）
  4. D1（云端账本）
    管「记账」：星星流水、答题记录的云端当前态落库（D1 文档）
  5. Cron（每日闹钟）
    管「后悔药」：每天给 D1 拍一次快照、留 30 天，误操作可整包回滚（Cron Triggers）

注意分工：取壳这条路和同步这条岔路，起点都是你的域名，但中间各站不同——前者终点是 Pages（只发文件），后者终点是 D1（记账）。分得清这两条路，你就有了评估任何部署方案的地基。11 个词的分工速查见术语表。

本课收尾

单一收获自查：不看上文，你能复述「现在这条路」的五站吗？能说出同步岔路比取壳多经过哪几站吗？说得出，这课就到手了。

第一手读物（primary source）：MDN 的 How the web works——客户端/服务器、DNS、HTTP 一站讲全，是本课地图的权威底图。想深挖某个词，再按 域名、DNS、CDN 各自的官方科普顺藤摸瓜。
