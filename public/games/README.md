# 游戏接入技术要求

你将为一个孩子答题 App 开发首页小游戏。宿主 App 是本地优先的静态站点（HTTPS 部署），首页有一个**付费游戏槽位**：孩子花"星星"开局，游戏在**同源 iframe** 中运行。你交付的目录会被原样放进站点 `/games/<你的游戏id>/` 下，宿主加载你的 `index.html`——换游戏对宿主是纯配置操作，因此你的游戏必须严格满足本契约。

**核心一句话：交付一个完全自包含的静态目录，实现既定的开局授权消息协议，不碰宿主的任何数据。**

游玩门槛（价格、开放时段、余额校验、扣费）全部由宿主管理，游戏无需也无法知晓这些信息。

## 1. 交付物

一个自包含目录，推荐结构：

```
games/<你的游戏id>/
├── index.html    # 必须：入口（直接打开=试玩模式；被 iframe 加载=嵌入模式）
├── icon.svg      # 必须：首页贴纸图标（规格见第 6 节）
├── *.js / *.css / 音频 / 图片 …   # 其余资源随意组织
└── README.md     # 建议：玩法与实现说明
```

- **全部资源相对路径引用**，整个目录可被任何静态服务器直接服务，无需构建步骤
- **离线口径**：禁止一切外部请求（CDN、字体、图片、业务接口、上报）；允许且仅允许加载本目录内的静态资源；**不得注册自己的 Service Worker**。离线可玩的保证由宿主负责（宿主当前无 Service Worker、加载需网络；若未来增加预缓存，会随站点构建覆盖游戏目录），游戏侧零责任
- ES modules 需要 HTTP(S) 环境（宿主天然满足；本地调试请起一个静态服务器，不要用 `file://`）

## 2. 运行环境

- 目标设备：**iPhone Safari 优先**（主 App 实际运行环境）；iPad 保持手机式单列流程，不做平板专属多列/横幅布局；最低支持 **iOS / Safari 15.4**
- 同源 iframe、HTTPS
- **触摸优先**：滑动 / 点按可完成全部操作，不得依赖键盘
- **视口自适应**：以 iframe 实际视口为准做 100% 流式**单列**布局，不得假设固定宽高；默认纵向（iPad 上同样是手机式单列，无横幅/多列预期）
- `localStorage` 不可用时降级为不保存最高分（try/catch 包裹读写），不得影响游玩
- 音频：WebAudio 必须在 iframe 内获得**真实用户触摸**后才能激活；收到开局授权后先显示"触摸出发"就绪层，用这次触摸激活音频；**音频失败不得阻塞已付费的游玩**（下次触摸重试即可）

## 3. 生命周期协议 v1（核心）

宿主与游戏通过 `window.postMessage` 通信，双方都必须校验 `event.origin` 与 `event.source`（只信任同源、只信任当前 iframe 窗口）；发送用 `postMessage(message, location.origin)`，**不使用通配目标源**。**宿主义务：先注册 message 监听，再加载 iframe**（缓存的游戏可能比监听器更早就绪，先监听可避免漏掉唯一一次 `ready`）。

游戏通过 `window.self !== window.top` 检测嵌入：顶层直接打开 = 试玩模式（可立即玩，用于开发调试）；iframe 内 = 嵌入模式（必须走本协议，不得绕过）。

每条消息恰好六个字段：

| 字段 | 类型与约束 | 含义 |
| --- | --- | --- |
| channel | 字符串，恒为你的游戏专属名 | 如 `maze-runner`；全局唯一、小写、连字符，与宿主槽位配置一致 |
| version | 数字 `1` | 协议版本 |
| type | 字符串 | `ready` / `start` / `ended` / `replay-request` / `exit` |
| instanceId | 非空字符串 | 游戏文档本次加载的实例标识（每次加载新生成，不复用） |
| requestId | 字符串，格式 `${instanceId}:N` | 实例内请求序号：初次 N=1，每局重玩递增 |
| roundId | 非空字符串；**尚未授权过任何一局时为 null**（初次 `ready`、未授权时的 `exit`） | 宿主签发的一次性局标识 |

游戏侧状态机：

1. 嵌入模式加载完成后发送 `ready`（roundId 为 null）。宿主核对来源与完整形状后等待人工确认
2. 宿主完成门槛校验与扣费后，签发新 roundId 并发送 `start`（其余字段与当前请求一致）。游戏校验全部通过才接受：channel/version 正确、**instanceId 是自己**、处于等待授权状态、requestId 匹配、**roundId 未使用过**、字段恰好六个——通过后进入已授权，显示"触摸出发"
3. 真实触摸后开始游玩
4. 本局结束时发送**一次** `ended`（带本局 requestId/roundId）
5. 用户选择重玩：发送 `replay-request`（requestId 加一，roundId 仍指向刚结束的那局）；宿主重新确认并扣费后才发来**全新的 roundId**。嵌入模式下不得自行免费重开
6. 用户退出：发送 `exit`，宿主销毁 iframe。`exit` 携带**当前 requestId + 当前 roundId**：未授权过 roundId 为 null；重玩等待期为新 requestId + 刚结束那局的 roundId。重建的 iframe 是新实例（新 instanceId），旧实例的剩余消息不得被接受

关于付费环节的异常（对方常见问题）：

- 宿主未确认付费、用户取消、余额不足：游戏停在等待授权状态——宿主要么稍后发来 `start`，要么直接销毁 iframe；游戏无需超时重发、无需任何处理
- **扣费异常政策（宿主单方面决定，游戏无权也无责处理）**：以「游戏是否就绪（已发出 `ready`）」为界——就绪前的失败（加载超时、加载失败、加载期间退出）宿主**自动全额退回星星**；就绪之后（游玩中退出、iframe 崩溃/刷新、本局结束后退出）不退款、不恢复本局，宿主 UI 已明示。宿主是记账唯一真相源，游戏侧状态不影响账务

防御性要求：旧请求、复用 roundId、游玩中重复授权、多余字段的消息一律拒绝处理。

**红线：消息不得携带价格、余额、分数、流水或孩子数据。**

## 4. 数据与安全

- **不读不写宿主的任何 localStorage 键**（经济账本、配置等一概不碰）；自己的持久化（如最高分）用自己的命名空间键，如 `<你的游戏id>.v1.best`
- 游戏得分只用于游戏内展示与结算，**绝不折算为 App 星星**
- 无网络上报、无第三方脚本、无跟踪
- **信任前提（明示）**：同源 iframe 在技术上可以访问宿主 DOM 与同源存储——本契约是开发约定 + 代码审核的信任边界，不是技术隔离。接入前提是游戏代码经接入方审核；未来若接入不可信第三方，需另行隔离方案（不同源部署或沙箱），不属于本契约范围
- 不必对抗开发者工具或直接访问静态资源的用户——宿主已接受此边界（静态资源不是权限服务器，协议的目的是生命周期与账目收口，不是防篡改）

## 5. 体验基调

- 单局约 1–3 分钟量级、可重玩、难度渐进（参考：同目录 `skate-boy/` 做过固定种子模拟校准）
- 自带 HUD 与视觉风格（游戏自己的 CSS 变量），不依赖宿主样式与组件
- **切后台 / 锁屏自动暂停**（`visibilitychange`），回来原地继续，不得判负——孩子切走不能白白输掉已付费的一局
- 建议尊重系统"减少动态效果"偏好（`prefers-reduced-motion`）：关闭装饰性动画，保留必要移动
- 无横竖屏强制要求，纵向单列为默认预期

## 6. icon.svg 规格

- 方形 viewBox、**透明背景**
- 用你自己的颜色画，简洁可辨识，缩小到约 48px 仍清晰
- **不要画外层描边**——宿主会统一施加与 App 主题匹配的贴纸描边（令牌驱动，你无需知道 App 主题）

## 7. 交付前自检清单

- [ ] 目录拷进任意静态站点的任意子路径，直接打开 `index.html` 可玩
- [ ] 断网状态下完整可玩（零外部请求；本地静态服务器起好后断网测试）
- [ ] 未注册任何 Service Worker
- [ ] 用同源演示页 iframe 嵌入，协议全链路通：`ready → start → ended → replay-request → 新 start → exit`
- [ ] 非法消息被拒绝：错 channel / 错 instanceId / 旧 requestId / 复用 roundId / 多余字段
- [ ] localStorage 只出现自己的命名空间键；隐私模式（存储禁用）下仍可玩
- [ ] 触摸全程可玩；音频无法激活时游玩不受阻；切后台回来原地继续
- [ ] icon.svg 符合第 6 节规格

## 8. 宿主侧接入手续（接入方操作，开发者无需关心）

目录放入 `public/games/<id>/`，修改宿主的槽位配置对象（id、名称、每局价格、开放时窗、入口路径、channel、图标路径、玩法说明文案）各一次，宿主代码零改动。
